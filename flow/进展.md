  4. **官方 6 个可变引脚只消费 3 个**：另外 3 个（UART1_TX/RX、TOUCH_PAD2）服务于官方固件的

- **教育内容(下一棒直接学会，不必再查)**：
  1. **`_1` / `_2` 后缀是 PCB 版本号，不是麦克风/通道编号**。`config.h` 的
     `AUDIO_I2S_GPIO_DIN_1/2`、`AUDIO_CODEC_PA_PIN_1/2`、`QSPI_PIN_NUM_LCD_RST_1/2` 里，
     `_1` = V1.0、`_2` = V1.2。`esp_vocat.cc:277-282` 把它们装进 6 个可写全局 `gpio_num_t`，
     `ApplyV12Pins()`(:700-707) 在探测到 V1.2 时整体切换。第一眼极易误读成「双麦两路数据线」——
     官方板只有**一根** I2S DIN。
  2. **为什么缓存路径也必须调 `ApplyV12Pins()`**：`GetAudioCodec()`(:1187) 是 lazy `static` 构造，
     在类构造函数之后才读那 6 个全局变量。软复位走缓存分支时若不切换，V1.2 会用 V1.0 的
     DIN=15 / PA=4，音频直接失效。
  3. **为什么 GPIO48 要「先写输出锁存器，再切成输出」**：外部复位后锁存器默认 0；
     若先 `gpio_config()` 配成输出，会瞬间把 V1.2 的 codec 电源轨拉低，首次触摸/电量计读失败并重启
     （官方 issue #1202）。顺序反了就是玄学重启。
  4. **为什么软复位不能重新探测 PCB 版本**：codec 电源轨有残余电荷，GPIO48 拉低时 ES8311 仍会假 ACK，
     被误判成 V1.0 → 电源被切断 → 未供电芯片经 ESD 二极管钳位共享 I2C 总线 → 重启循环。
     所以用 `RTC_NOINIT_ATTR` + magic `0x31434256` 缓存，只在真正的上电复位时探测。
  5. **I2C 地址有两套表示**：`i2c_master_probe()` 用 7-bit（ES8311 0x18 / ES7210 0x40 /
     CST816S 0x15 / 电量计 0x55），`audio_codec_i2c_cfg_t.addr` 用 8-bit（0x30 / 0x80，
     即左移一位）。写错地址表现为「probe 成功但 codec 初始化失败」。
  6. **`muse_board_t.codec_power` 正好对应 CORDEC_POWER_CTRL**：框架已预留 codec 供电开关回调，
     但本板的 GPIO48 同时是版本探测脚，反复断电会丢 codec 寄存器，所以首次适配建议留 NULL 常供电，
     别机械绑定（方案文档 5.3）。
  7. **框架的板级边界**：一个板文件只填 `muse_board_t` + `muse_board_get()`，
     UI/语音/网络全在共享层；CMake 的 `elseif` 链保证同一时刻只链接一个板文件，
     所以所有板都能导出同名 `muse_board_get()` 而不冲突。新增板要改的是
     Kconfig / CMakeLists / idf_component.yml / overlay / 板文件 / 工具脚本 / 文档，
     **不是**重写业务。`idf_component.yml` 的 rules 只能用 `MUSE_BOARD_ID`。
